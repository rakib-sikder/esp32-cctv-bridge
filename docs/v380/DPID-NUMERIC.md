# V380 IoT property IDs — computed numeric values

Generated by simulating the `static {}` block in `Protocol.java` (the app builds these
at class-load, so they are never written as literals in the source). Formula per id:

    DPID = (item & 0xFF) | ((group & 0xFF) << 16) | 0x100   // property (read/write)
    DAID = ... | 0x200                                      // action (do-something)
    DEID = ... | 0x300                                      // event (device -> app)
    DFID = ... | 0x400                                      // file (list/upload/download)

So the class byte at bits 8-11 tells you WHAT KIND of id it is, the byte at bits 16-23
is the feature group (DGID), and the low byte is the index within that group.

NOTE: group 14 is shared by DET and ALERT_V2 (both DGID=14, both index from 0), so those
ids genuinely overlap — ALERT_V2 is the newer event-model naming over the same group.
